# 四节点嵌入 Playbook：AI/人配对细则

> 核心原则：**每个节点必须写成"AI 做什么 + 人做什么（不可让渡项）"的配对。** 只有 AI 侧的节点是单点提效，人没被重新定位，链路不成立。

## 节点 1：分析/选品

### AI 做
- 市场容量扫描（类目搜索量、趋势斜率）
- 竞品集中度（CR5/CR10、头部 ASIN 份额）
- 价格带分布（主力价格带、空档价格带）
- 评论挖掘（差评关键词聚类 = 未满足需求）

### 人做（不可让渡）
- **拍板"做/不做"**：AI 给证据，人给决策；决策依据要写进清单（为什么做：哪个证据；为什么不做：哪个风险）
- 品牌定位校准：AI 扫出来的空档，是不是你的品牌该填的空档（定位错位的空档是陷阱）
- 供应链可行性判断：这个品你能不能做出差异化（同质化空档 = 红海假象）

### 输出物："做/不做"清单模板

```markdown
# 选品决策清单（日期）
| 候选 | 容量证据 | 集中度 | 价格带空档 | 决策 | 依据（一句话） |
|---|---|---|---|---|---|
| A | 搜索量周均 12w，斜率 +8% | CR5=38% | $15-20 空档 | 做 | 空档+集中度可接受 |
| B | 搜索量 40w | CR5=81% | 无 | 不做 | 头部垄断，新进入无差异化 |

工时对比：人工一周（5 天）→ AI+人半天（4 小时）
```

**判据**：输出是**清单**（带决策+依据），不是报告（带分析但没有决策）。报告 = AI 替代了分析但人还在自己拍板；清单 = 人的判断被压缩成了"拍板"这一不可让渡动作。

## 节点 2：内容（listing/主图/文案/A+）

### AI 做
- listings 初稿（标题五点描述，含卖点词与搜索词布局）
- 主图文案初稿、A+ 页面结构初稿
- 多语言/多站点版本适配初稿

### 人做（不可让渡）
- **品牌语气校准**：AI 初稿的通用语气 → 品牌声调（这个词该不该说、这个梗该不该玩）
- **合规审查**：广告法、平台禁词、品类合规（医疗/食品/儿童类目的声称限制）——这一条出事就是账号问题，不可让渡给 AI
- 卖点优先级终审：AI 会平均用力，人决定哪个卖点是第一视觉

### 断点检查
- 内容是否按**节点 1 的"做/不做"清单**生产（不是按运营感觉）
- listing 卖点词是否传给节点 3（投放按 listing 卖点配关键词，不是另起一套词）

## 节点 3：投放/运营

### AI 做
- 广告结构分组（按卖点/价格带/人群分层）
- 关键词分层（大词/精准词/长尾词的出价梯度）
- 否定词清理（周期性跑搜索词报告，聚类无效词）
- 异常检测（ACOS 突刺、转化掉线的预警）

### 人做（不可让渡）
- **预算分配**：钱往哪压是策略判断（新品期烧钱换数据 vs 成熟期收割）
- **止损线设定**：单 ASIN ACOS 红线、单广告组连续 N 天无转化的下线规则——AI 执行止损，人定止损线

### 断点检查
- 投放数据是否**回流节点 1**（哪些词/卖点转化差 → 下一轮选品与 listing 修订）
- 没有回流 = 投放是孤岛，链路没通

## 节点 4：服务/客服

### AI 做
- 常见问答模板化（Top 20 问题 × 标准答案）
- 工单分类与优先级初判
- 评价情感监测（差评预警）

### 人做（不可让渡）
- **升级投诉处理**（退款纠纷、账号申诉、平台沟通——措辞错一步是封号风险）
- **评价危机处置**（差评回复策略、品牌声誉判断）
- 模板维护决策：哪些问题该进模板、哪些必须人答

### 断点检查
- 客服高频问题是否**回流节点 1/2**（"用户反复问什么" = 选品/内容的真实需求信号）

## 节点对齐检查表（链路 vs 单点的分界线）

```
链路定义：上游输出 = 下游输入
  节点1 "做/不做"清单 ──→ 节点2 按清单生产内容    [断点？]
  节点2 listing 卖点 ───→ 节点3 按卖点配关键词    [断点？]
  节点3 投放数据 ───────→ 节点1 下一轮选品        [断点？]
  节点4 客服高频问题 ───→ 节点1/2 需求信号        [断点？]
```

**任一断点存在 = 不是链路，是四个单点提效拼在一起。**
- 单点提效的天花板：省人力（每节点独立算工时节省）
- 链路级的价值：**成本结构变轻**（环节间不再互相打架，信息不损耗地流动）

## 断点诊断法

发现"链路没通"时的诊断顺序（别急着加工具）：
1. **输出格式断**：上游输出是报告不是清单 → 先改上游输出格式（让下游能用）
2. **传递断**：格式对但没传（还在 Excel 里躺着）→ 建传递机制（固定表/看板/流程文档）
3. **消费断**：传了但下游不看（各干各的）→ 把"用上游输出"写进下游 SOP（第 1 步动作）
4. **回流断**：下游数据没回上游 → 建周期回流（周报固定栏/月度复盘固定议程）

**80% 的断点是 1 和 3**：不是缺 AI，是输出格式和 SOP 没写。先修这两个，再谈加模型。
